# MODX3 MCP

**MODX3 MCP** — MCP-сервер и компонент для **MODX Revolution 3.x**, который позволяет ИИ-агентам работать с сайтом через структуру и API самого MODX, а не напрямую с базой данных или набором файлов.

> **MODX3 MCP не пытается дать ИИ максимальный доступ к сайту. Он пытается дать ИИ правильный доступ к MODX.**

Проект основан на оригинальном [**modxMCP**](https://github.com/dampilov94/mcp-component) (автор — [**dampilov94**](https://github.com/dampilov94)) и существенно переработан для MODX Revolution 3.x: добавлена поддержка современного API MODX 3, расширен набор операций, усилены механизмы безопасности и реализованы средства анализа структуры сайта и последствий изменений.

Текущая версия: **1.0.0**.

Поддерживаемая ветка MODX: **3.x**.

## Идея проекта

Обычный доступ ИИ к серверу позволяет редактировать файлы, выполнять SQL-запросы и запускать команды. Для MODX этого недостаточно: значительная часть структуры сайта хранится в ресурсах, шаблонах, чанках, сниппетах, TV-полях, системных настройках, связях между объектами и данных установленных дополнений.

MODX3 MCP предоставляет агенту специализированный слой управления, который понимает эти сущности и работает с ними как с объектами MODX.

Это позволяет агенту не просто «редактировать сайт», а:

- находить ресурсы, шаблоны, чанки, сниппеты, плагины и TV-поля;
- анализировать связи и зависимости между элементами;
- определять, где используется изменяемый элемент;
- создавать, изменять и удалять объекты MODX через контролируемые операции;
- работать с системными настройками, источниками файлов и дополнительными подсистемами;
- выполнять предварительную проверку опасных операций;
- автоматически создавать резервные копии перед изменениями;
- разделять операции чтения и операции, изменяющие сайт;
- передавать сведения об изменениях во внешний журнал.

Главная задача проекта — сделать работу ИИ-агента с MODX **предсказуемой, проверяемой и обратимой**.

## Почему MODX3 MCP устроен именно так

MODX3 MCP создавался не как демонстрация возможности подключить LLM к MODX, а как инструмент для практической работы с реальными сайтами.

При использовании ИИ-агентов основная проблема обычно заключается не в том, способен ли агент изменить файл или запись в базе данных. Гораздо важнее, понимает ли он последствия этого изменения.

На рабочем MODX-сайте один элемент редко существует изолированно. Чанк может использоваться десятками ресурсов и шаблонов, TV-поле — участвовать в логике нескольких разделов, а системная настройка — влиять на работу компонента целиком. Изменение небольшого на первый взгляд элемента способно затронуть значительную часть сайта.

Поэтому в MODX3 MCP сделан упор не только на выполнение команд, но и на контекст изменения: поиск зависимостей, предварительную проверку, резервное копирование, разделение операций чтения и записи, ограничение потенциально опасных действий и возможность аудита.

Цель проекта — не сделать агента всесильным. Цель — дать ему достаточно информации и ограничений, чтобы он реже принимал опасные решения вслепую.

## Типичные ошибки ИИ при работе с CMS

Практическая работа ИИ с CMS отличается от работы с обычным набором файлов. Агент может технически выполнить правильную команду, но при этом не учитывать контекст, скрытые зависимости или особенности конкретного сайта.

| Типичная проблема | Что может произойти | Что делает MODX3 MCP |
| --- | --- | --- |
| Изменение элемента без проверки его использования | Агент изменяет общий чанк, сниппет или TV-поле и затрагивает несколько разделов сайта | Позволяет исследовать зависимости и места использования элемента |
| Прямое изменение базы данных | Обход логики MODX, нарушение связей между объектами или некорректная работа кеширования | Предоставляет специализированные операции над объектами MODX |
| Удаление объекта только потому, что он кажется неиспользуемым | Скрытая зависимость обнаруживается уже после поломки части сайта | Позволяет анализировать связи и оценивать возможные последствия до удаления |
| Перезапись настроек при обновлении | Теряются API-токен или параметры, настроенные для конкретного сайта | При повторной установке и обновлении существующие значения настроек сохраняются |
| Несколько одновременных изменений | Один процесс может перезаписать результат другого | Для изменяющих операций предусмотрена блокировка параллельной работы |
| Ошибка во время изменения | Сайт может остаться в промежуточном или частично изменённом состоянии | Используются резервные копии и безопасная схема замены файлов при установке |
| Слишком широкие возможности агента | Ошибка затрагивает больше объектов и подсистем, чем требовалось | Отдельные группы возможностей можно отключать и ограничивать |
| Нет истории действий | После изменения сложно понять, что именно выполнял агент | Поддерживается внешний журнал операций и передача данных для аудита |

## Чем отличается этот подход

MODX3 MCP не заменяет SSH, SQL или доступ к файлам. Он решает другую задачу: предоставляет ИИ интерфейс, в котором структура MODX сохраняет свой смысл.

| Подход | Что получает агент | Основное ограничение |
| --- | --- | --- |
| SSH и командная строка | Широкий доступ к серверу, файлам и системным командам | Агент получает большие полномочия, но почти не получает сведений о структуре и зависимостях CMS |
| Прямой доступ к SQL | Возможность читать и изменять данные в таблицах | Прикладная логика MODX обходится, а структура таблиц не объясняет назначение и связи объектов |
| Универсальный MCP для файлов | Удобную работу с исходным кодом и файловой системой | Значительная часть данных и структуры MODX хранится не в файлах |
| Универсальный MCP для базы данных | Доступ к таблицам и запросам | База данных показывает данные, но не объясняет агенту семантику объектов MODX и последствия их изменения |
| MODX3 MCP | Специализированные операции над сущностями MODX и сведения об их взаимосвязях | Агент ограничен возможностями, которые явно реализованы и разрешены сервером |

MODX3 MCP сознательно не предоставляет ИИ произвольный доступ ко всему серверу. Вместо этого он старается дать агенту более узкий, но семантически богатый интерфейс: ресурс остаётся ресурсом, чанк — чанком, TV — TV, а зависимости между ними можно исследовать до внесения изменений.

## Возможности

Серверная часть MODX3 MCP содержит более 180 операций, которые клиент объединяет в набор специализированных MCP-инструментов.

Поддерживается работа с основными объектами MODX Revolution:

- ресурсы и структура сайта;
- шаблоны;
- чанки;
- сниппеты;
- плагины и их события;
- TV-поля и их значения;
- категории;
- системные настройки;
- пространства имён;
- источники файлов и медиа;
- группы пользователей и права доступа;
- наборы свойств;
- контексты;
- пакеты и дополнения;
- словари;
- MIGX;
- miniShop2;
- VersionX;
- VirtualPage.

Доступность отдельных групп функций можно ограничивать настройками компонента.

## Анализ зависимостей

Одна из ключевых возможностей MODX3 MCP — построение графа зависимостей между элементами сайта.

Агент может определить:

- какие чанки и сниппеты используются шаблоном;
- какие TV-поля связаны с шаблонами;
- какие элементы вызывают другие элементы;
- где используется конкретный элемент;
- какие ссылки ведут на отсутствующие элементы;
- какие элементы, вероятно, больше нигде не используются;
- какие части сайта могут быть затронуты изменением.

Граф можно использовать как через MCP, так и через отдельный экран в менеджере MODX.

Это особенно важно для больших проектов, где изменение одного чанка, сниппета или TV-поля может повлиять сразу на несколько разделов сайта.

## Безопасность изменений

MODX3 MCP проектировался не только для чтения данных, но и для реальной работы агента с действующим сайтом.

Поэтому операции, изменяющие сайт, отделены от операций чтения и могут использовать дополнительные механизмы защиты.

В зависимости от операции поддерживаются:

- автоматические резервные копии перед изменением;
- предварительный просмотр результата без внесения изменений;
- дополнительное подтверждение для разрушительных операций;
- блокировка параллельных изменений проекта;
- ограничение доступных групп команд;
- отдельное разрешение на выполнение произвольных процессоров MODX;
- обязательная работа API по HTTPS по умолчанию;
- безопасная проверка API-токена;
- автоматический выбор только активного пользователя MODX с правами администратора;
- сохранение существующих настроек и токена при обновлении компонента.

Клиент также может передавать сведения о выполненных изменениях во внешний журнал.

## Ограничения и модель доверия

MODX3 MCP не делает работу ИИ безошибочной.

LLM по-прежнему может неправильно понять задачу, выбрать неподходящий объект или предложить нежелательное изменение. Компонент уменьшает технические риски и предоставляет агенту больше контекста, но не заменяет резервное копирование сайта, контроль доступа и проверку критических изменений человеком.

Особенно осторожно следует относиться к массовым операциям, изменению прав доступа, системных настроек, пользовательского PHP-кода и операциям сторонних дополнений.

Для рабочего сайта рекомендуется предоставлять агенту только те группы операций, которые действительно необходимы для текущих задач.

## Внешний журнал изменений

Для интеграции с собственной системой аудита предусмотрена переменная:

`MODX_MCP_AUDIT_HOOK`

В ней указывается абсолютный путь к исполняемой программе.

После успешно выполненной операции, изменяющей сайт, клиент передаёт этой программе через стандартный ввод JSON с информацией об операции:

- название MCP-инструмента;
- аргументы;
- результат;
- идентификатор сайта;
- сведения об исполнителе;
- пути к автоматически созданным резервным копиям.

Внешняя программа запускается напрямую, без командной оболочки.

Если обработчик аудита не настроен, работа MODX3 MCP не меняется. Ошибка внешнего обработчика также не превращает уже успешно выполненное изменение сайта в ошибку.

Операции только для чтения внешний обработчик не вызывают.

## Совместимость

MODX3 MCP предназначен для:

**MODX Revolution >= 3.0.0 и < 4.0.0**

Основная разработка и практическое тестирование версии 1.0.0 выполнялись на **MODX Revolution 3.2.4-pl**.

Дополнительно совместимость процессоров и основных операций проверялась на:

- MODX Revolution 3.2.2-pl;
- MODX Revolution 3.2.4-pl;
- актуальной ветке MODX Revolution 3.x.

Для работы MCP-клиента требуется **Node.js 18 или новее**.

### Среда разработки и внешний интерфейс

В процессе разработки для удалённой работы с ИИ-агентом использовался открытый проект [**cc-connect**](https://github.com/chenhg5/cc-connect), созданный [**Glenn (chenhg5)**](https://github.com/chenhg5). Он использовался как связующий слой между агентом и системой обмена сообщениями.

Внешний интерфейс управления проектом был реализован через **Telegram-бота собственной разработки**. Через него можно было ставить задачи агенту, получать результаты и работать с проектом удалённо.

## Установка через транспортный пакет MODX

Для обычной установки рекомендуется использовать готовый транспортный пакет:

`modx3mcp-1.0.0-pl.transport.zip`

Последнюю стабильную версию можно скачать в разделе **Releases** этого репозитория.

После загрузки пакет устанавливается стандартными средствами MODX.

Установка создаёт:

- компонент MODX3 MCP;
- системные настройки `modxmcp.*`;
- пространство имён `modxmcp`;
- пункты меню менеджера;
- серверную часть API;
- интерфейс настройки компонента;
- экран графа зависимостей.

API-токен создаётся автоматически при первой установке.

При повторной установке или обновлении существующие значения настроек и токен сохраняются.

## Установка из командной строки

Для серверов, которыми управляет агент или система автоматизации, компонент можно установить без регистрации пакета в менеджере пакетов MODX.

```bash
php _build/install.headless.php
```

Если `config.core.php` расположен вне дерева проекта:

```bash
MODX_CONFIG_CORE=/full/path/to/config.core.php php _build/install.headless.php
```

Сценарий установки:

- проверяет версию MODX;
- создаёт необходимые настройки и пункты меню;
- устанавливает файлы компонента;
- автоматически создаёт API-токен, если его ещё нет;
- сохраняет существующие настройки при обновлении;
- сначала подготавливает новую версию файлов во временных каталогах;
- заменяет рабочие каталоги только после успешной подготовки;
- восстанавливает предыдущую версию файлов при ошибке установки.

Установка выполняется только из командной строки и не создаёт доступного из браузера установщика.

## Подключение MCP-клиента

Для стабильной версии 1.0.0:

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": [
        "-y",
        "github:rumata-estor/modx3-mcp#v1.0.0"
      ],
      "env": {
        "MODX_MCP_SITE_URL": "https://example.com/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "ваш-токен"
      }
    }
  }
}
```

Для разработки вместо тега версии можно использовать ветку `modx3`:

```text
github:rumata-estor/modx3-mcp#modx3
```

Для рабочих сайтов рекомендуется закреплять конкретную версию.

## Проверка релизной сборки

В репозитории находятся автоматические проверки, которые используются перед выпуском новой версии.

Проверяются:

- синтаксис PHP;
- синтаксис Node.js-клиента;
- соответствие версий во всех файлах проекта;
- соответствие клиентских инструментов серверным операциям;
- переносимость установки;
- безопасные значения настроек по умолчанию;
- совместимость процессоров с несколькими версиями MODX 3;
- установка транспортного пакета;
- повторная установка с сохранением настроек;
- удаление компонента без оставшихся файлов и настроек.

Для отдельного тестового сайта полный цикл можно запустить командой:

```bash
MODX_CONFIG_CORE=/full/path/to/config.core.php bash _build/release.smoke.sh
```

Перед выпуском MODX3 MCP 1.0.0 дополнительно была выполнена чистая установка на отдельный MODX Revolution 3.2.4-pl, проверена работа MCP-клиента, изменение тестовых объектов, повторная установка с сохранением настроек и полное удаление компонента.
