# MODX3 MCP

**MODX3 MCP** — MCP-сервер (**Model Context Protocol**) и компонент для **MODX Revolution 3.x**, который позволяет ИИ-агентам работать с сайтом через структуру и API самого MODX, а не напрямую с базой данных или набором файлов.

> **MODX3 MCP не пытается дать ИИ максимальный доступ к сайту. Он пытается дать ИИ правильный доступ к MODX.**

Проект основан на оригинальном [**modxMCP**](https://github.com/dampilov94/mcp-component), автор исходного проекта — [**dampilov94**](https://github.com/dampilov94). MODX3 MCP существенно переработан для MODX Revolution 3.x: обновлён слой работы с API MODX, расширен набор операций, усилены механизмы безопасности и добавлен анализ структуры сайта и зависимостей.

**Версия [1.0.0](https://github.com/rumata-estor/modx3-mcp/releases/tag/v1.0.0) · MODX Revolution 3.x · MIT**

## Идея проекта

Обычный доступ ИИ к серверу позволяет редактировать файлы, выполнять SQL-запросы и запускать команды. Для MODX этого недостаточно: значительная часть структуры сайта хранится в ресурсах, шаблонах, чанках, сниппетах, TV-полях, системных настройках, связях между объектами и данных установленных дополнений.

MODX3 MCP предоставляет агенту специализированный слой управления, который работает с этими сущностями как с объектами MODX. Агент может:

- находить ресурсы, шаблоны, чанки, сниппеты, плагины и TV-поля;
- анализировать связи и места использования элементов;
- создавать, изменять и удалять объекты MODX через контролируемые операции;
- работать с системными настройками, источниками файлов и поддерживаемыми дополнениями;
- предварительно проверять потенциально опасные операции;
- создавать резервные копии перед изменениями;
- разделять операции чтения и изменения;
- передавать сведения об изменениях во внешний журнал.

Главная задача проекта — сделать работу ИИ-агента с MODX **предсказуемой, проверяемой и обратимой**.

## Кому пригодится MODX3 MCP

Проект рассчитан прежде всего на:

- разработчиков и интеграторов MODX, использующих ИИ-агентов в повседневной работе;
- агентства и команды, сопровождающие несколько MODX-проектов;
- владельцев сложных MODX-сайтов, которым нужен контролируемый доступ ИИ к CMS;
- разработчиков собственных агентных систем, которым недостаточно общего доступа к файлам, SSH или базе данных.

## Почему MODX3 MCP устроен именно так

MODX3 MCP создавался не как демонстрация подключения LLM к CMS, а как инструмент для практической работы с реальными сайтами.

Главный риск при работе ИИ-агента — не в том, сможет ли он изменить файл или запись, а в том, понимает ли он последствия изменения. На рабочем MODX-сайте один элемент редко существует изолированно: общий чанк может использоваться десятками ресурсов и шаблонов, TV-поле — участвовать в логике нескольких разделов, а системная настройка — влиять на работу компонента целиком.

Поэтому в MODX3 MCP сделан упор не только на выполнение команд, но и на контекст: зависимости, предварительную проверку, резервное копирование, ограничение потенциально опасных действий и аудит.

Цель проекта — не сделать агента всесильным, а дать ему достаточно информации и ограничений, чтобы он реже принимал опасные решения вслепую.

## Среда разработки и агентная архитектура

MODX3 MCP разрабатывался и проверялся в составе рабочей агентной среды, используемой для практического сопровождения сайтов.

Для связи ИИ-агента с системой обмена сообщениями использовался открытый проект [**cc-connect**](https://github.com/chenhg5/cc-connect), созданный [**Glenn (chenhg5)**](https://github.com/chenhg5).

В нашей рабочей среде внешний интерфейс реализован с помощью **Telegram-бота и серверных скриптов собственной разработки**. Они размещены в закрытом репозитории как часть внутренней инфраструктуры и авторских наработок (ноу-хау).

> **MODX3 MCP — это сервер и набор инструментов для агента, а не готовый агент и не привязанный к Telegram интерфейс.**

Node.js-часть MODX3 MCP запускается как локальный MCP-сервер через `stdio`. Поэтому MODX3 MCP можно использовать с любым клиентом или агентной средой, которая умеет запускать и подключать MCP-серверы такого типа: средой разработки, собственным агентом, системой автоматизации или подходящим чат-интерфейсом.

Пользователь может написать собственные инструкции для агента и самостоятельно определить правила его работы с MODX3 MCP. Telegram-бот — только один из вариантов интерфейса, использованный в нашей рабочей схеме.

Отдельной частью этой инфраструктуры является **AGENT.md** — разработанный нами набор системных инструкций, ограничений и рабочих правил для ИИ-агента. Он сформирован на основе более чем двухлетней практической работы с сайтами с применением искусственного интеллекта. Часть накопленных правил напрямую повлияла на архитектуру MODX3 MCP: анализ зависимостей, разделение операций чтения и изменения, резервное копирование, ограничения опасных действий и аудит.

Telegram-бот, серверные скрипты и AGENT.md **не являются зависимостями MODX3 MCP** и не требуются для его установки или использования.

## Типичные ошибки ИИ при работе с CMS

| Типичная проблема | Возможное последствие | Что делает MODX3 MCP |
| --- | --- | --- |
| Изменение элемента без проверки его использования | Общий чанк, сниппет или TV-поле затрагивает несколько разделов сайта | Позволяет исследовать зависимости и места использования элемента |
| Прямое изменение базы данных | Обход логики MODX, нарушение связей или некорректное кэширование | Предоставляет специализированные операции над объектами MODX |
| Удаление «неиспользуемого» объекта без проверки | Скрытая зависимость обнаруживается уже после поломки части сайта | Позволяет анализировать связи и оценивать последствия до удаления |
| Перезапись настроек при обновлении | Теряются API-токен или параметры конкретного сайта | Существующие значения настроек сохраняются при повторной установке и обновлении |
| Несколько одновременных изменений | Один процесс перезаписывает результат другого | Для изменяющих операций предусмотрена блокировка параллельной работы |
| Ошибка во время обновления компонента | Установка остаётся в неполном состоянии | Новая версия файлов подготавливается отдельно, а при ошибке предыдущие каталоги восстанавливаются |
| Слишком широкие возможности агента | Ошибка затрагивает больше объектов, чем требовалось | Отдельные группы возможностей можно отключать и ограничивать |
| Нет истории действий | Сложно установить, что именно выполнял агент | Поддерживается внешний журнал операций и передача данных для аудита |

## Чем отличается этот подход

MODX3 MCP не заменяет SSH, SQL или доступ к файлам. Он решает другую задачу: предоставляет ИИ интерфейс, в котором структура MODX сохраняет свой смысл.

| Подход | Что получает агент | Основное ограничение |
| --- | --- | --- |
| SSH и командная строка | Широкий доступ к серверу и системным командам | Большие полномочия без понимания структуры CMS |
| Прямой доступ к SQL | Чтение и изменение данных в таблицах | Обход прикладной логики MODX и слабое понимание связей объектов |
| Универсальный MCP для файлов | Работа с кодом и файловой системой | Значительная часть структуры MODX хранится не в файлах |
| Универсальный MCP для базы данных | Доступ к таблицам и запросам | Таблицы не объясняют агенту семантику объектов MODX |
| MODX3 MCP | Специализированные операции над сущностями MODX и их взаимосвязями | Агент ограничен возможностями, которые явно реализованы и разрешены сервером |

MODX3 MCP сознательно не предоставляет ИИ произвольный доступ ко всему серверу. Вместо этого он даёт более узкий, но семантически богатый интерфейс: ресурс остаётся ресурсом, чанк — чанком, TV — TV, а зависимости между ними можно исследовать до внесения изменений.

## Пример практической задачи

Например, агенту можно поставить задачу:

> «Увеличь цену товаров определённой категории на 100 ₽. Сначала определи, где хранится цена, проверь затрагиваемые объекты и только потом внеси изменения».

Вместо прямого изменения таблиц агент может через MODX3 MCP исследовать структуру проекта, определить нужные сущности, оценить связанные объекты, выполнить изменение доступными операциями и зафиксировать результат.

## Возможности

Серверная часть MODX3 MCP содержит более 180 операций, которые клиент объединяет в специализированные MCP-инструменты.

Поддерживается работа с:

- ресурсами и структурой сайта;
- шаблонами, чанками и сниппетами;
- плагинами и событиями;
- TV-полями и их значениями;
- категориями и системными настройками;
- пространствами имён;
- источниками файлов и медиа;
- группами пользователей и правами доступа;
- наборами свойств и контекстами;
- пакетами, дополнениями и словарями;
- MIGX, miniShop2, VersionX и VirtualPage.

Отдельные группы функций можно отключать настройками компонента.

## Анализ зависимостей

Одна из ключевых возможностей MODX3 MCP — построение графа зависимостей между элементами сайта.

[![Граф зависимостей MODX3 MCP](docs/images/dependency-graph.png)](docs/images/dependency-graph.png)

*Граф зависимостей MODX3 MCP в менеджере MODX: связи между шаблонами, чанками, сниппетами, TV-полями и плагинами, а также обнаруженные битые ссылки и неиспользуемые элементы.*

Агент может определить:

- какие чанки и сниппеты используются шаблоном;
- какие TV-поля связаны с шаблонами;
- какие элементы вызывают другие элементы;
- где используется конкретный элемент;
- какие ссылки ведут на отсутствующие элементы;
- какие элементы, вероятно, больше нигде не используются;
- какие части сайта могут быть затронуты изменением.

Граф доступен как через MCP, так и через отдельный экран в менеджере MODX. Это особенно полезно на больших проектах, где изменение одного элемента может повлиять сразу на несколько разделов сайта.

## Безопасность изменений

MODX3 MCP рассчитан не только на чтение данных, но и на реальную работу агента с действующим сайтом. В зависимости от операции поддерживаются:

- автоматические резервные копии перед изменением;
- предварительный просмотр без внесения изменений;
- дополнительное подтверждение разрушительных операций;
- блокировка параллельных изменений;
- ограничение доступных групп команд;
- отдельное разрешение на выполнение произвольных процессоров MODX;
- обязательная работа API по HTTPS по умолчанию;
- безопасная проверка API-токена;
- автоматический выбор только активного пользователя MODX с правом `sudo`;
- сохранение существующих настроек и токена при обновлении компонента.

## Ограничения и модель доверия

MODX3 MCP не делает работу ИИ безошибочной. LLM может неправильно понять задачу, выбрать неподходящий объект или предложить нежелательное изменение.

Компонент уменьшает технические риски и даёт агенту больше контекста, но не заменяет резервное копирование сайта, контроль доступа и проверку критических изменений человеком. Особенно осторожно следует относиться к массовым операциям, правам доступа, системным настройкам, пользовательскому PHP-коду и операциям сторонних дополнений.

Для рабочего сайта рекомендуется разрешать агенту только те группы операций, которые действительно необходимы.

## Внешний журнал изменений

Для интеграции с собственной системой аудита предусмотрена переменная `MODX_MCP_AUDIT_HOOK`.

После успешно выполненной операции, изменяющей сайт, клиент может запустить указанную локальную программу и передать ей через стандартный ввод JSON с названием MCP-инструмента, аргументами, результатом, идентификатором сайта, сведениями об исполнителе и путями к автоматически созданным резервным копиям.

Программа запускается напрямую, без командной оболочки. Если обработчик не настроен, обычная работа MODX3 MCP не меняется. Ошибка внешнего обработчика не превращает уже выполненное изменение сайта в ошибку. Операции только для чтения обработчик не вызывают.

## Совместимость

MODX3 MCP предназначен для:

**MODX Revolution >= 3.0.0 и < 4.0.0**

Основная разработка и практическое тестирование версии 1.0.0 выполнялись на **MODX Revolution 3.2.4-pl**.

Дополнительно совместимость процессоров и основных операций проверялась на:

- MODX Revolution 3.2.2-pl;
- MODX Revolution 3.2.4-pl;
- актуальной ветке MODX Revolution 3.x.

Для запуска локального MCP-сервера требуется **Node.js 18 или новее**.

## Быстрый старт

Минимальный рабочий сценарий:

1. Установить транспортный пакет MODX3 MCP.
2. Получить автоматически созданный API-токен.
3. Подключить MCP-клиент к серверу MODX3 MCP.
4. Начать с безопасной задачи только для чтения, например: «Покажи структуру проекта и зависимости шаблона X».

После этого агент можно подключать к более сложным сценариям, постепенно разрешая только необходимые группы операций.

## Установка через транспортный пакет MODX

Для обычной установки используйте готовый транспортный пакет:

`modx3mcp-1.0.0-pl.transport.zip`

Он доступен в [релизе MODX3 MCP 1.0.0](https://github.com/rumata-estor/modx3-mcp/releases/tag/v1.0.0) и устанавливается стандартными средствами MODX.

Установка создаёт компонент MODX3 MCP, системные настройки `modxmcp.*`, пространство имён, пункты меню менеджера, API и экран графа зависимостей. API-токен создаётся автоматически при первой установке.

При повторной установке или обновлении существующие значения настроек и токен сохраняются.

## Установка из командной строки

Для серверов, которыми управляет агент или система автоматизации, компонент можно установить без регистрации пакета в менеджере пакетов MODX:

```bash
php _build/install.headless.php
```

Если `config.core.php` расположен вне дерева проекта:

```bash
MODX_CONFIG_CORE=/full/path/to/config.core.php php _build/install.headless.php
```

Сценарий установки проверяет версию MODX, создаёт необходимые настройки и пункты меню, устанавливает файлы и при необходимости генерирует API-токен. Новая версия файлов сначала подготавливается во временных каталогах; при ошибке предыдущие каталоги восстанавливаются.

Установка выполняется только из командной строки и не создаёт доступного из браузера установщика.

## Настройка MCP-клиента

Для стабильной версии 1.0.0:

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": [
        "-y",
        "github:rumata-estor/modx3-mcp#v1.0.0"
      ],
      "env": {
        "MODX_MCP_SITE_URL": "https://example.com/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "ваш-токен"
      }
    }
  }
}
```

Для разработки вместо тега версии можно использовать ветку `modx3`:

```text
github:rumata-estor/modx3-mcp#modx3
```

Для рабочих сайтов рекомендуется закреплять конкретную версию.

## Проверка релизной сборки

Перед выпуском проверяются:

- синтаксис PHP и Node.js-клиента;
- соответствие версий и клиентских инструментов серверным операциям;
- переносимость установки и безопасные значения настроек;
- совместимость процессоров с несколькими версиями MODX 3;
- установка, повторная установка с сохранением настроек и полное удаление транспортного пакета.

Полный цикл на отдельном тестовом сайте:

```bash
MODX_CONFIG_CORE=/full/path/to/config.core.php bash _build/release.smoke.sh
```

Перед выпуском версии 1.0.0 дополнительно была выполнена чистая установка на MODX Revolution 3.2.4-pl, проверены MCP-клиент, изменение тестовых объектов, повторная установка с сохранением настроек и полное удаление компонента.
