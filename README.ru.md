# MODX MCP

**MODX MCP** — MCP-сервер (**Model Context Protocol**) и линия компонентов для **MODX Revolution 2.8.x и 3.x**. ИИ-агент работает через объекты, процессоры, права и связи MODX, а не воспринимает сайт только как базу данных и набор файлов.

> **MODX MCP не пытается дать ИИ максимальный доступ к сайту. Он пытается дать ИИ правильный доступ к MODX.**

Проект основан на оригинальном [**modxMCP**](https://github.com/dampilov94/mcp-component), автор — [**dampilov94**](https://github.com/dampilov94). Текущая кодовая база выросла из переноса на MODX 3 и теперь использует единый модульный Runtime с платформенными адаптерами для MODX 2 и MODX 3.

**Версия исходников 1.1.0 · MODX Revolution 2.8.x / 3.x · 182/182 модульных действия · MIT**

> Имя репозитория `modx3-mcp`, имя Node-пакета и существующие технические идентификаторы сохранены ради обратной совместимости. В документации и менеджере MODX отображаемое название теперь — **MODX MCP**.


## Идея проекта

Обычный доступ ИИ к серверу позволяет редактировать файлы, выполнять SQL-запросы и запускать команды. Для MODX этого недостаточно: значительная часть структуры сайта хранится в ресурсах, шаблонах, чанках, сниппетах, TV-полях, системных настройках, связях между объектами и данных установленных дополнений.

MODX MCP предоставляет агенту специализированный слой управления, который работает с этими сущностями как с объектами MODX. Агент может:

- находить ресурсы, шаблоны, чанки, сниппеты, плагины и TV-поля;
- анализировать связи и места использования элементов;
- создавать, изменять и удалять объекты MODX через контролируемые операции;
- работать с системными настройками, источниками файлов и поддерживаемыми дополнениями;
- предварительно проверять потенциально опасные операции;
- создавать резервные копии перед изменениями;
- разделять операции чтения и изменения;
- передавать сведения об изменениях во внешний журнал.

Главная задача проекта — сделать работу ИИ-агента с MODX **предсказуемой, проверяемой и обратимой**.

## Кому пригодится MODX MCP

Проект рассчитан прежде всего на:

- разработчиков и интеграторов MODX, использующих ИИ-агентов в повседневной работе;
- агентства и команды, сопровождающие несколько MODX-проектов;
- владельцев сложных MODX-сайтов, которым нужен контролируемый доступ ИИ к CMS;
- разработчиков собственных агентных систем, которым недостаточно общего доступа к файлам, SSH или базе данных.

## Почему MODX MCP устроен именно так

MODX MCP создавался не как демонстрация подключения LLM к CMS, а как инструмент для практической работы с реальными сайтами.

Главный риск при работе ИИ-агента — не в том, сможет ли он изменить файл или запись, а в том, понимает ли он последствия изменения. На рабочем MODX-сайте один элемент редко существует изолированно: общий чанк может использоваться десятками ресурсов и шаблонов, TV-поле — участвовать в логике нескольких разделов, а системная настройка — влиять на работу компонента целиком.

Поэтому в MODX MCP сделан упор не только на выполнение команд, но и на контекст: зависимости, предварительную проверку, резервное копирование, ограничение потенциально опасных действий и аудит.

Цель проекта — не сделать агента всесильным, а дать ему достаточно информации и ограничений, чтобы он реже принимал опасные решения вслепую.

## Среда разработки и агентная архитектура

MODX MCP разрабатывался и проверялся в составе рабочей агентной среды, используемой для практического сопровождения сайтов.

Для связи ИИ-агента с системой обмена сообщениями использовался открытый проект [**cc-connect**](https://github.com/chenhg5/cc-connect), созданный [**Glenn (chenhg5)**](https://github.com/chenhg5).

В нашей рабочей среде внешний интерфейс реализован с помощью **Telegram-бота и серверных скриптов собственной разработки**. Они размещены в закрытом репозитории как часть внутренней инфраструктуры и авторских наработок (ноу-хау).

> **MODX MCP — это сервер и набор инструментов для агента, а не готовый агент и не привязанный к Telegram интерфейс.**

Node.js-часть MODX MCP запускается как локальный MCP-сервер через `stdio`. Поэтому MODX MCP можно использовать с любым клиентом или агентной средой, которая умеет запускать и подключать MCP-серверы такого типа: средой разработки, собственным агентом, системой автоматизации или подходящим чат-интерфейсом.

Пользователь может написать собственные инструкции для агента и самостоятельно определить правила его работы с MODX MCP. Telegram-бот — только один из вариантов интерфейса, использованный в нашей рабочей схеме.

Отдельной частью этой инфраструктуры является **AGENT.md** — разработанный нами набор системных инструкций, ограничений и рабочих правил для ИИ-агента. Он сформирован на основе более чем двухлетней практической работы с сайтами с применением искусственного интеллекта. Часть накопленных правил напрямую повлияла на архитектуру MODX MCP: анализ зависимостей, разделение операций чтения и изменения, резервное копирование, ограничения опасных действий и аудит.

Telegram-бот, серверные скрипты и AGENT.md **не являются зависимостями MODX MCP** и не требуются для его установки или использования.

## Типичные ошибки ИИ при работе с CMS

| Типичная проблема | Возможное последствие | Что делает MODX MCP |
| --- | --- | --- |
| Изменение элемента без проверки его использования | Общий чанк, сниппет или TV-поле затрагивает несколько разделов сайта | Позволяет исследовать зависимости и места использования элемента |
| Прямое изменение базы данных | Обход логики MODX, нарушение связей или некорректное кэширование | Предоставляет специализированные операции над объектами MODX |
| Удаление «неиспользуемого» объекта без проверки | Скрытая зависимость обнаруживается уже после поломки части сайта | Позволяет анализировать связи и оценивать последствия до удаления |
| Перезапись настроек при обновлении | Теряются API-токен или параметры конкретного сайта | Существующие значения настроек сохраняются при повторной установке и обновлении |
| Несколько одновременных изменений | Один процесс перезаписывает результат другого | Для изменяющих операций предусмотрена блокировка параллельной работы |
| Ошибка во время обновления компонента | Установка остаётся в неполном состоянии | Новая версия файлов подготавливается отдельно, а при ошибке предыдущие каталоги восстанавливаются |
| Слишком широкие возможности агента | Ошибка затрагивает больше объектов, чем требовалось | Отдельные группы возможностей можно отключать и ограничивать |
| Нет истории действий | Сложно установить, что именно выполнял агент | Поддерживается внешний журнал операций и передача данных для аудита |

## Чем отличается этот подход

MODX MCP не заменяет SSH, SQL или доступ к файлам. Он решает другую задачу: предоставляет ИИ интерфейс, в котором структура MODX сохраняет свой смысл.

| Подход | Что получает агент | Основное ограничение |
| --- | --- | --- |
| SSH и командная строка | Широкий доступ к серверу и системным командам | Большие полномочия без понимания структуры CMS |
| Прямой доступ к SQL | Чтение и изменение данных в таблицах | Обход прикладной логики MODX и слабое понимание связей объектов |
| Универсальный MCP для файлов | Работа с кодом и файловой системой | Значительная часть структуры MODX хранится не в файлах |
| Универсальный MCP для базы данных | Доступ к таблицам и запросам | Таблицы не объясняют агенту семантику объектов MODX |
| MODX MCP | Специализированные операции над сущностями MODX и их взаимосвязями | Агент ограничен возможностями, которые явно реализованы и разрешены сервером |

MODX MCP сознательно не предоставляет ИИ произвольный доступ ко всему серверу. Вместо этого он даёт более узкий, но семантически богатый интерфейс: ресурс остаётся ресурсом, чанк — чанком, TV — TV, а зависимости между ними можно исследовать до внесения изменений.

## Пример практической задачи

Например, агенту можно поставить задачу:

> «Увеличь цену товаров определённой категории на 100 ₽. Сначала определи, где хранится цена, проверь затрагиваемые объекты и только потом внеси изменения».

Вместо прямого изменения таблиц агент может через MODX MCP исследовать структуру проекта, определить нужные сущности, оценить связанные объекты, выполнить изменение доступными операциями и зафиксировать результат.

## Возможности

Серверная часть MODX MCP содержит более 180 операций, которые клиент объединяет в специализированные MCP-инструменты.

Поддерживается работа с:

- ресурсами и структурой сайта;
- шаблонами, чанками и сниппетами;
- плагинами и событиями;
- TV-полями и их значениями;
- категориями и системными настройками;
- пространствами имён;
- источниками файлов и медиа;
- группами пользователей и правами доступа;
- наборами свойств и контекстами;
- пакетами, дополнениями и словарями;
- MIGX, miniShop2, VersionX и VirtualPage.

Отдельные группы функций можно отключать настройками компонента.

## Анализ зависимостей

Одна из ключевых возможностей MODX MCP — построение графа зависимостей между элементами сайта.

[![Граф зависимостей MODX MCP](docs/images/dependency-graph.png)](docs/images/dependency-graph.png)

*Граф зависимостей MODX MCP в менеджере MODX: связи между шаблонами, чанками, сниппетами, TV-полями и плагинами, а также обнаруженные битые ссылки и неиспользуемые элементы.*

Агент может определить:

- какие чанки и сниппеты используются шаблоном;
- какие TV-поля связаны с шаблонами;
- какие элементы вызывают другие элементы;
- где используется конкретный элемент;
- какие ссылки ведут на отсутствующие элементы;
- какие элементы, вероятно, больше нигде не используются;
- какие части сайта могут быть затронуты изменением.

Граф доступен как через MCP, так и через отдельный экран в менеджере MODX. Это особенно полезно на больших проектах, где изменение одного элемента может повлиять сразу на несколько разделов сайта.

## Безопасность изменений

MODX MCP рассчитан не только на чтение данных, но и на реальную работу агента с действующим сайтом. В зависимости от операции поддерживаются:

- автоматические резервные копии перед изменением;
- предварительный просмотр без внесения изменений;
- дополнительное подтверждение разрушительных операций;
- блокировка параллельных изменений;
- ограничение доступных групп команд;
- отдельное разрешение на выполнение произвольных процессоров MODX;
- обязательная работа API по HTTPS по умолчанию;
- безопасная проверка API-токена;
- автоматический выбор только активного пользователя MODX с правом `sudo`;
- сохранение существующих настроек и токена при обновлении компонента.

## Ограничения и модель доверия

MODX MCP не делает работу ИИ безошибочной. LLM может неправильно понять задачу, выбрать неподходящий объект или предложить нежелательное изменение.

Компонент уменьшает технические риски и даёт агенту больше контекста, но не заменяет резервное копирование сайта, контроль доступа и проверку критических изменений человеком. Особенно осторожно следует относиться к массовым операциям, правам доступа, системным настройкам, пользовательскому PHP-коду и операциям сторонних дополнений.

Для рабочего сайта рекомендуется разрешать агенту только те группы операций, которые действительно необходимы.

## Внешний журнал изменений

Для интеграции с собственной системой аудита предусмотрена переменная `MODX_MCP_AUDIT_HOOK`.

После успешно выполненной операции, изменяющей сайт, клиент может запустить указанную локальную программу и передать ей через стандартный ввод JSON с названием MCP-инструмента, аргументами, результатом, идентификатором сайта, сведениями об исполнителе и путями к автоматически созданным резервным копиям.

Программа запускается напрямую, без командной оболочки. Если обработчик не настроен, обычная работа MODX MCP не меняется. Ошибка внешнего обработчика не превращает уже выполненное изменение сайта в ошибку. Операции только для чтения обработчик не вызывают.

## Совместимость

Версия 1.1.0 — первая общая линия исходников для двух поддерживаемых поколений MODX:

- **MODX Revolution 2.8.x** — платформенная сборка `modx2`;
- **MODX Revolution 3.x** — платформенная сборка `modx3`;
- для локального MCP-сервера требуется **Node.js 18 или новее**.

Обе ветки MODX используют один MCP-клиент, один публичный набор действий и один модульный Runtime. Различия загрузки, имён классов и маршрутов процессоров изолированы в платформенных адаптерах и release overlay.

Текущий статус проверки:

- все **182/182** серверных действия зарегистрированы в модульном Runtime;
- MODX 3.2.4-pl прошёл полный live regression;
- совместимость процессоров MODX 3 проверяется на 3.2.2-pl, 3.2.4-pl и актуальной ветке 3.x;
- release staging и статическая/PHP-совместимость MODX 2 проходят;
- перед публикацией 1.1.0 как окончательного стабильного релиза нужен отдельный live release-smoke на реальном MODX 2.

Точная матрица описана в [архитектуре сборки](docs/BUILD-ARCHITECTURE.ru.md) и [статусе валидации](docs/VALIDATION.ru.md).

## Быстрый старт

Минимальный рабочий сценарий:

1. Установить транспортный пакет MODX MCP.
2. Получить автоматически созданный API-токен.
3. Подключить MCP-клиент к серверу MODX MCP.
4. Начать с безопасной задачи только для чтения, например: «Покажи структуру проекта и зависимости шаблона X».

После этого агент можно подключать к более сложным сценариям, постепенно разрешая только необходимые группы операций.

## Установка через транспортный пакет MODX

Из одной кодовой базы версии 1.1.0 собираются два платформенных transport-пакета:

- MODX 2.8.x: `modxmcp-1.1.0-pl.transport.zip`;
- MODX 3.x: `modx3mcp-1.1.0-pl.transport.zip`.

Устанавливайте только пакет, соответствующий основной версии MODX. Оба пакета устанавливают одно пространство имён `modxmcp`, одинаковые настройки, MCP endpoint и один набор модульных действий.

При повторной установке или обновлении существующие настройки `modxmcp.*` и API-токен сохраняются.

Пока live release-smoke на MODX 2 не завершён, 1.1.0 считается версией исходников/кандидатом в релиз, а последним опубликованным стабильным релизом GitHub остаётся 1.0.1.

## Установка из командной строки

Исходное дерево репозитория по умолчанию соответствует сборке MODX 3. Для явной платформенной установки сначала создайте чистое release-дерево.

MODX 3:

```bash
python3 _build/prepare-release.py --platform modx3 --output /tmp/modxmcp-modx3
cd /tmp/modxmcp-modx3
MODX_CONFIG_CORE=/full/path/to/config.core.php php _build/install.headless.php
```

MODX 2:

```bash
python3 _build/prepare-release.py --platform modx2 --output /tmp/modxmcp-modx2
cd /tmp/modxmcp-modx2
MODX_CONFIG_CORE=/full/path/to/config.core.php php _build/install.headless.php
```

В подготовленную сборку попадает только выбранный платформенный fallback/bootstrap; исходные legacy/platform-шаблоны в релиз не включаются.

Установщик создаёт нужные настройки и пункты менеджера и при необходимости генерирует API-токен. Новые файлы сначала подготавливаются отдельно, а существующие настройки и токен при обновлении сохраняются.

## Настройка MCP-клиента

Для версии 1.1.0 после публикации релиза закрепляйте тег:

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": [
        "-y",
        "github:rumata-estor/modx3-mcp#v1.1.0"
      ],
      "env": {
        "MODX_MCP_SITE_URL": "https://example.com/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "ваш-токен"
      }
    }
  }
}
```

Node.js-клиент один и тот же для MODX 2 и MODX 3; отличается только серверный transport-пакет.

Для разработки и проверки до релиза используйте:

```text
github:rumata-estor/modx3-mcp#main
```

На рабочих сайтах рекомендуется закреплять опубликованный тег релиза.

## Проверка релизной сборки

Перед выпуском проверяются:

- синтаксис PHP и Node.js-клиента;
- согласованность версии в общей кодовой базе и обеих платформенных build-конфигурациях;
- полный контракт клиента и сервера: **182 действия**;
- модульное покрытие: **74/74 read + 108/108 mutations**;
- release staging и PHP-совместимость MODX 2;
- процессоры MODX 3 на 3.2.2-pl, 3.2.4-pl и актуальной ветке 3.x;
- переносимость установки, безопасные настройки и корректные ограничения transport-пакета для каждой платформы;
- install/reinstall/uninstall smoke на отдельном тестовом сайте соответствующей версии MODX.

Перед полным smoke сначала подготовьте release-дерево нужной платформы. Никогда не запускайте разрушительный release-smoke на рабочем сайте.

## Происхождение проекта

MODX MCP создан на основе открытого проекта [**modxMCP**](https://github.com/dampilov94/mcp-component), автор исходного проекта — [**dampilov94**](https://github.com/dampilov94).

Исходная работа и сведения об авторстве сохранены в истории проекта и лицензии. MODX MCP развивает исходную основу в общую платформу для MODX 2/3: с анализом зависимостей, контролем изменяющих операций, резервным копированием, аудитом и платформенными адаптерами.

## Лицензия и релиз

Проект распространяется по лицензии **MIT**. См. [LICENSE](LICENSE).

Текущая версия исходников / кандидат в релиз: **1.1.0**.

Последний опубликованный стабильный релиз: **[1.0.1](https://github.com/rumata-estor/modx3-mcp/releases/tag/v1.0.1)** — до завершения отдельного live release-smoke на MODX 2.

Для релиза 1.1.0 предусмотрены исходный архив, отдельные transport-пакеты для MODX 2 и MODX 3 и их контрольные суммы SHA-256.

---

MODX MCP можно установить и настроить самостоятельно по документации. В реальных проектах интеграция нередко требует отдельной настройки прав доступа, безопасных сценариев, резервного копирования, аудита, сторонних дополнений и особенностей конкретного сайта. Такие задачи обычно требуют отдельной инженерной работы вокруг конкретного проекта.
